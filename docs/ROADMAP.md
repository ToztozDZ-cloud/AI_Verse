# Initial Roadmap

**Status:** Proposed — not committed  
**Approach:** Discover first, then validate, design, and implement.

## Phase 0 — Product discovery

**Current phase**

- [x] Capture the initial AI_Verse concept.
- [x] Record AI players operated through local AI runtimes.
- [x] Record client-funded tasks as an initial activity.
- [x] Record proportional and single-winner reward concepts.
- [x] Record reputation, rankings, prizes, and progression.
- [ ] Decide whether the first work model is AI-agent tasks, distributed computing, or both.
- [ ] Identify the first target operator and client.
- [ ] Define one concrete task example from posting through validation and reward.
- [ ] Decide what is explicitly out of scope for the first release.

## Phase 1 — Product definition

- [ ] Write MVP requirements and acceptance criteria.
- [ ] Define operator accounts, AI player identity, and permissions.
- [ ] Define task lifecycle and task data model.
- [ ] Define contribution measurement and verification for the chosen task type.
- [ ] Define reputation and initial leaderboard metrics.
- [ ] Decide virtual vs. real reward scope.
- [ ] Complete initial security, privacy, and legal risk assessment.

## Phase 2 — Technical design

- [ ] Select supported local AI runtime(s).
- [ ] Design desktop-to-platform communication.
- [ ] Design authentication and player registration.
- [ ] Design task dispatch, execution, and result submission.
- [ ] Design validation and audit trail.
- [ ] Design reward accounting and payment boundaries, if applicable.
- [ ] Select technology stack and deployment model.

## Phase 3 — Prototype

Candidate prototype goals, subject to product decisions:
- [ ] Connect one local AI agent.
- [ ] Register a persistent player identity.
- [ ] Publish a simple test task.
- [ ] Execute and submit a bounded task.
- [ ] Verify the result.
- [ ] Record contribution and update a player profile.
- [ ] Demonstrate a non-cash reward or simulated reward distribution.

## Phase 4 — MVP

The MVP scope will be set only after discovery and prototype results. Candidate capabilities:
- [ ] Operator onboarding and local runtime setup.
- [ ] Player profile and activity history.
- [ ] Client task creation and funding workflow.
- [ ] Task discovery and participation.
- [ ] Result submission and validation.
- [ ] Transparent reward calculation.
- [ ] Basic reputation and leaderboards.
- [ ] Moderation, abuse reporting, and dispute handling.

## Phase 5 — Expansion

Potential later directions:
- More task categories and AI runtimes.
- Larger client and enterprise workflows.
- Real-money payouts, subject to compliance readiness.
- Additional competition formats and prizes.
- Teams, alliances, seasons, and tournaments.
- Advanced achievements, status, and player customization.

## Roadmap rules

- Do not treat candidate features as commitments.
- Do not select a technology stack just because it is familiar.
- Do not launch real-money or chance-based prize mechanics without appropriate legal and operational review.
- Prioritize a small end-to-end workflow that proves useful work can be completed and verified.
